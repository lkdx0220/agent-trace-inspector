## 1. 项目定位

`Agent Trace Inspector` 是**原神剧情助手项目专用的观测 + 评测 + 诊断平台**，不是通用 Agent 平台。

它解决三个问题：

1. 原项目 Agent 跑完之后，有没有可审计的完整轨迹？
2. 25 道 Golden Test 跑完后，哪些题失败、为什么失败？
3. 失败题的根因，能否被一条可复现的、有证据链的“项目医生”定位出来？

核心原则：

- **只读**观察原项目，不修改原项目核心行为；
- **确定性优先**：能代码判定的，不让 LLM 猜；
- **证据链闭环**：每条诊断/处方必须能对应到真实 Trace、工具返回、知识库原始数据或源码；
- **版本隔离**：历史 Trace 不能被当前工作区代码“污染”式归因。

## 3. 当前架构（已实现）

### 3.1 Trace 采集与导出

- `exporter/genshin_exporter.py`
  - `build_trace_from_result(...)`：从原项目运行结果构造 Trace；
  - `_enrich_trace_with_events(...)`、`_add_missing_llm_spans_from_events(...)`、`_fill_assess_router_times(...)`：补全事件与时间；
  - 支持 `--context` 注入上一轮对话；
  - 支持 `project_path`，自动生成 `source_snapshot`。
- Trace Schema：`schemas/trace.py`
  - `Trace`：`schema_version=0.1`、`trace_id`、`agent`、`question`、`metadata`、`root_span`、`trace_events`、`source_snapshot`；
  - `Span`：`span_type`（agent/rewrite/assess/router/llm/tool/answer）、状态、`result_preview/result_full`、`tool_args`、`tool_calls`；
  - `TraceMetadata`：`execution_mode`、`intent_labels`、`alias_notes`、`response_mode` 等；
  - `SourceSnapshot`：`git_commit`、`git_dirty`、`dirty_files`、关键文件 SHA256。

### 3.2 存储层

- 主库：`data/inspector.db`（SQLite）。
- 表：
  - `traces`：Trace 完整 JSON、`intent_labels`、`response_mode`；
  - `spans`：Span 数据；
  - `trace_events`：原始事件；
  - `test_cases`：Golden Test 题目、`must_contain`、`must_not_contain`、`match_mode`、`alternatives`；
  - `runs`：Run 总览 + `results_json`（逐题结果）；
  - `diagnoses`：AI 诊断报告；
  - `prescriptions`：项目医生完整输出；
  - `case_audits`：Passed 题轻量审计。
- 文件产物：
  - `data/traces/*.json`：Trace 样本；
  - `data/reports/*.md`：运行分析报告；
  - `data/case_metadata_full.json`：25 题语义元数据；
  - `data/tmp/`：医生子进程探针临时文件（自动清理）。

### 3.3 确定性评测层

`app/services/evaluator.py`：

- 关键词评测：`evaluate_keywords(answer, case)`；
- 支持 `match_mode=all/any`、双答案 `alternatives`；
- `SEMANTIC_ALLOWED_KEYWORDS`：只有少量通用语义词走轻量 LLM 判词；
- 专名/书名/角色名等必须精确字符串命中；
- 工具/路由评测：检查实际工具调用、`expected_route`（L1/L2）；
- 系统提示词合规：`check_prompt_compliance(trace, project_path)`。

`app/services/lab_orders.py` 会从评测失败 reasons 生成强制检查单。

### 3.4 报告与诊断层

- `app/services/report_generator.py`
  - 基于题目元数据 + 工具返回证据，生成自然语言运行分析报告；
  - 不输出修改建议，只做分析；
  - Markdown 转 HTML 展示。
- `app/services/diagnoser.py`
  - 轻量 AI 归因：`root_cause / evidence / suggestion / confidence`；
  - 注入系统提示词合规检查与工具规则摘要。
- `app/services/case_audit.py`
  - 对 passed 题做轻量审计：确定性相似度（Jaccard/containment/keyword rate）+ 短路识别；
  - 可选 DeepSeek 轻量 LLM 复核；
  - 用于发现“虽然 passed，但答案其实是未收录/短路”的可疑通过。

### 3.5 项目医生（当前实现，核心）

当前医生采用“**LLM 驱动采证 + 多道闸门**”模式。

流程：

1. 从 Run/Case/Trace 生成 `lab_orders`；
2. 构造系统提示词，加入项目地图、版本快照、LabOrder 清单；
3. LLM（默认 `qwen3.7-max`）通过 function calling 调只读工具：
   - `run_lab_check`：执行强制检查单；
   - `read_project_file` / `grep_project` / `read_system_prompt`；
   - `search_knowledge_base` / `inspect_raw_kb` / `inspect_aliases`；
   - `evidence_search` / `evidence_view`；
   - `record_verified_claim` / `pin_fact`。
4. 编排器自动补齐未完成的 LabOrder（覆盖闸门）；
5. LLM 输出最终 JSON，经过：
   - `validate_prescriptions`：证据 ID 必须存在；
   - `_final_grounding_check`：根因必须字面接地，并按结论类型检查证据性质；
   - `_near_miss_gate`：不允许轻易归为“知识库真缺/题目设置/无需修改”；
   - `_conclusion_consistency_gate`：`conclusion_kind` + `fact_assertions` 必须与 FactSheet 一致；
6. 全部通过才保存；否则回喂错误继续迭代；
7. 超过轮次后走 `_fallback_report`（确定性候选处方，不 0 处方）。

当前主要代码：

| 模块 | 职责 |
|---|---|
| `app/services/project_doctor.py` | 医生主循环、提示词、闸门、fallback |
| `app/services/doctor_tools.py` | 只读探查工具、`run_lab_check`、证据回看 |
| `app/services/lab_orders.py` | 从失败原因生成检查单 |
| `app/services/coverage_gate.py` | 覆盖度、evidence_ids 校验 |
| `app/services/project_map.py` | 项目文件/函数地图 |
| `app/services/source_snapshot.py` | Trace 版本快照与当前版本比对 |
| `app/services/rate_limit.py` | API 限流 |

### 3.6 API 与前端

- `app/routers/traces.py`：Trace 导入/列表/详情/时间线/指标；
- `app/routers/eval.py`：TestCases、Runs、报告、诊断、passed 审计、对比；
- `app/routers/doctor.py`：医生诊断 POST/GET；
- `static/app.js`：Trace 详情、时间线、耗时图、批量评测、Runs、报告、医生视图；
- XSS：前端 `sanitizeHtml(...)` 对所有 `innerHTML` 赋值做净化；
- API 限流：医生 5/60s、诊断 10/60s、导入 30/60s。

### 3.7 当前已知问题与教训

1. **医生按失败原因“临时生成检查项”**：
   - 遇到 F1 类“路由没暴露工具”时，因为 LabOrder 只从“缺关键词”生成，医生根本没查路由层。
2. **LLM 承担了“该查什么”的职责**：
   - 模型能力足够，但它“看不到”没被放进上下文/检查单的字段；
   - 复杂病例（R2，10 条 LabOrder、5 个缺失词）会在采证上耗尽轮次，最后 fallback。
3. **版本污染**：
   - 历史 Trace 运行时的代码/提示词与当前工作区不一致，不能直接归因；
   - 已通过 `source_snapshot` 缓解，但仍需在医生提示词中强调。
4. **API Key 单一**：
   - 主 Key 失效会导致医生/诊断/报告全部 401；
   - 已增加 `DASHSCOPE_FALLBACK_API_KEY` 自动重试。
5. **补丁式迭代**：
   - 每次发现新漏洞就加一个检查项，长期会变成“规则堆”，缺少统一因果模型。

## 4. 迭代后目标架构：确定性因果链工作流

### 4.1 核心变化

从

> “LLM 根据失败原因决定查什么，然后自己归因”

改为

> “代码先完整跑一遍 Agent 因果链，生成 FactSheet 和唯一失败层，LLM 只负责解释与开方”。

### 4.2 八个确定性阶段

| 阶段 | 检查内容 | 输出 Fact |
|---|---|---|
| `input` | 问题、别名标注、rewrite | `alias_notes`、`rewritten_query` |
| `routing` | 路由标签、实际注入工具、按语义应暴露工具 | `route_intent_labels`、`injected_tools`、`missing_required_tools` |
| `planning` | plan 文本、tool_calls、tool_skip_reason、plan_retry | `plan_intents`、`actual_tool_calls`、`plan_tool_call_names` |
| `tool_execution` | 每个工具的 status/args/result/truncation | `tool_results`、`not_found_tools`、`error_tools` |
| `knowledge_truth` | 关键词/实体在原始知识库是否存在 | `raw_data_contains`、`alias_map_contains` |
| `answer` | 最终答案与工具语料、短路、禁止词、幻觉 | `final_answer_contains`、`short_circuit`、`forbidden_source` |
| `version` | Trace 快照 vs 当前工作区 | `prompt_snapshot_clean`、`code_snapshot_clean` |
| `evaluator` | raw Trace 事实 vs reasons | `evaluator_discrepancies` |

### 4.3 CausalResolver（因果梯子）

固定顺序，命中最上游即判定失败层：

```
1 routing_failure
   应暴露工具未暴露
2 plan_output_failure
   工具已暴露但未调用/选错
3 query_alias_failure
   工具返回 not_found，但原始数据/别名映射存在
4 recall_snippet_failure
   知识库存在且检索命中，但返回 snippet 未覆盖关键段落
5 answer_composition
   工具返回已含关键信息，但最终答案未使用/短路
6 answer_contamination
   禁止词/幻觉来自工具、提示词或答案自造
7 evaluator_error
   raw Trace 事实与 reasons 直接矛盾
8 version_unknown
   无法证明当前规则等于 Trace 时刻规则，只给当前版本建议
```

### 4.4 新的医生主流程（伪代码）

```
1. 读取 run/case/trace
2. 生成 stage-based LabOrders（固定 8 阶段 + 关键词细节）
3. 编排器自动执行全部 LabOrder
4. 构建 FactSheet
5. CausalResolver 判定唯一失败层 + evidence_ids
6. 构造系统提示词：
   - FactSheet（结构化）
   - 判定层（硬约束）
   - 项目地图 + 版本快照
7. LLM 只允许：
   - 在给定失败层内解释根因
   - 对每条处方绑定 evidence_ids
   - 补充可执行、防过拟合的修改建议
8. 一致性/接地/版本闸门校验：
   - prescription 的 conclusion_kind == 判定层
   - fact_assertions 由 FactSheet 自动核对
   - 版本不确定时禁止历史违规断言
9. 保存
```
