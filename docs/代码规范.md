# Agent Trace Inspector 代码规范

目标：让代码可以被人类 Python 程序员低负担维护。规范不靠记忆，靠 `pyproject.toml` + pre-commit + CI 自动执行。

## 1. 唯一配置入口

- 工具配置统一放在仓库根 `pyproject.toml`：
  - `[tool.ruff]` / `[tool.ruff.lint]` / `[tool.ruff.format]`
  - `[tool.mypy]` 与 `[[tool.mypy.overrides]]`
  - `[tool.pytest.ini_options]`
- 不再新增 `quality/ruff.toml`、`quality/mypy.ini` 之类的分散配置。
- `quality/importlinter.ini` 与 `quality/requirements.txt` 保留为工具专用配置。

## 2. 自动执行

- 本地：`pre-commit install` 后，每次提交自动跑 ruff check、ruff format、mypy、pytest smoke。
- CI：`.github/workflows/quality.yml` 在 push / PR 时执行 `python tools/quality_gate.py`。
- 手动全量：`python tools/quality_gate.py`；结果写入 `quality/reports/quality_gate_latest.json`。

## 3. 格式与 lint

- 统一使用 `ruff format`，行长 120，双引号，LF。
- lint 启用高信号规则：`E9`、`F`、`B`、`I`。
- 提交前必须通过 `ruff format --check`；禁止靠人工保持格式一致。

## 4. 类型标注

- 公共函数、方法、模块级函数必须有完整参数与返回类型标注。
- `schemas/`、`evaluator/`、`app/`、`exporter/`、`tools/` 已在 `pyproject.toml` 中开启：
  - `disallow_untyped_defs = true`
  - `check_untyped_defs = true`
- 优先使用 `Dict[str, Any]`、`List[...]`、`Optional[...]`；避免无信息量的裸 `Any`，除非是动态加载模块、第三方返回值等确实无法静态描述的场景。
- 新增模块若暂时无法过 mypy，先修类型，不要用 `# type: ignore` 绕过；确需 ignore 必须写原因。

## 5. 命名

- 模块 / 函数 / 变量：`snake_case`。
- 类 / Pydantic 模型 / dataclass：`PascalCase`。
- 常量：`UPPER_SNAKE_CASE`。
- 仅模块内部使用的 helper：`_leading_underscore`。
- 不用拼音缩写；中文注释可以，标识符用英文。

## 6. 异常处理

- 禁止裸 `except:`。
- 禁止 `except Exception: pass` 静默吞错。
- 允许在子系统边界（LLM 调用、网络请求、子进程、外部文件解析）统一捕获 `Exception`，但必须满足至少一条：
  - 记录/返回明确错误信息；
  - 返回安全的降级结果；
  - 由上层统一转成 HTTP 状态码。
- HTTP 路由层用 `HTTPException`，不要让底层异常直接暴露给客户端。
- 错误信息不得包含 API Key、完整请求头、绝对敏感路径。
- 质量门有 `except-hygiene` 检查：`except Exception` 处理体只有 `pass`/`continue`/`break` 时，必须在同一行写 `# boundary:` 说明这是外部边界，否则 FAIL。

## 7. 常量与路径

- 路径、模型名、超时、窗口大小等配置集中在模块级常量或 `app/services/*` 配置函数中。
- 禁止在代码里写死 `C:/Users/...`；项目根通过 `app/services/path_guard.py` 白名单校验。
- 知识库目录、embedding backend 只允许成对出现，由 `app/services/subprocess_env.py` 统一校验。

## 8. 测试

- 测试放 `tests/`，文件名 `test_*.py`，测试函数 `test_*`。
- 优先纯函数测试；不依赖网络/真实 LLM。
- 真实病例回归夹具放 `data/regression/fixtures/`（已 gitignore）；没有夹具时测试应 `skip`，不能让公开 CI 失败。
- 覆盖率由质量门把关：低于 25% FAIL，低于 30% WARN。

## 9. 复杂度

- `radon` 的 D/E/F 级函数直接 FAIL；C 级允许。
- 出现 D/E/F 时优先拆 helper，不要靠 `# noqa` 绕过。

## 10. 安全

- 后端返回的 HTML 必须经过 `app/services/html_sanitizer.py` 或前端 `sanitizeHtml()`。
- 原项目只读：不修改被测项目，不把被测项目 import 进 inspector 进程。
- 子进程探针必须用 JSON payload 传参，不把外部输入拼进 Python 源码。
- 提交前检查：不得提交 `.env`、运行数据、日志、`runs/`、`data/`。

## 11. Git 提交

- commit 使用类型前缀：`feat:`、`fix:`、`refactor:`、`test:`、`chore:`、`style:`、`docs:`。
- 纯格式化单独一个 `style:` commit，避免和逻辑改动混在一起。
- 推送使用可用代理：`git -c http.proxy=http://127.0.0.1:20808 push origin main`（按本机实际代理调整）。
